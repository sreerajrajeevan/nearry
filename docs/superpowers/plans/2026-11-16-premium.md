# Nearry Premium Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Google Play subscription (Nearry Premium) that removes the free daily limits (3 plans, 10 join requests) and unlocks a server-enforced "Hosted by" filter on the Nearby feed.

**Architecture:** The server is the source of truth. A `premium_entitlements` row (written only by an edge function that asks RevenueCat) decides who is Premium. Database triggers enforce the daily limits, and a premium-gated database function powers the host-gender filter. The app uses the RevenueCat SDK only to show prices and buy or restore. After each purchase it asks the same edge function to re-sync, so the server knows at once.

**Tech Stack:** Supabase Postgres (plpgsql migrations, PGlite tests), Supabase Edge Functions (Deno, handler code in `_shared` tested under tsx), Expo SDK 54 / RN 0.81, `react-native-purchases` (RevenueCat).

**Spec:** `docs/superpowers/specs/2026-11-16-premium-design.md`

## Global Constraints

- Prices: ₹49 / week, ₹149 / month, ₹349 / 3 months (set in Play Console; the app shows Google's localized price strings, never hard-coded prices).
- Free daily limits: **3** new plans and **10** join requests per India day (`(now() at time zone 'Asia/Kolkata')::date`). Premium is unlimited but still counted.
- Error messages raised by the database, verbatim: `daily_plan_limit`, `daily_join_limit`, `premium_required`.
- Host gender values: `female`, `male`, `other`. `other` is shown as **Non-binary**. "Everyone" means no filter.
- The women-only audience setting (`posts.gender_preference`) is untouched and stays free.
- No user may read another profile's `gender`. Gender filtering happens only inside security-definer SQL.
- Premium is for personal accounts only. Business accounts never see it.
- RevenueCat entitlement id `premium`. App env var `EXPO_PUBLIC_REVENUECAT_ANDROID_KEY`. Function secrets `REVENUECAT_WEBHOOK_SECRET` and `REVENUECAT_API_KEY`.
- Without the RevenueCat key (web, old builds) or in demo mode, nothing breaks. Premium shows as unavailable, and purchasing is disabled in demo mode.
- Follow repo checks before each commit: `npm run typecheck`, `npm test`, `npx prettier --check src tests`, `npm run sql:check` (after `npm run sql:generate`) when SQL changed.

## Review Focus

1. **Server inserts and seed data must not be limited.** Limits apply only when `auth.uid()` is the acting user. Admin tools, seeds and test fixtures inserting as the service role are never blocked (Task 1 test).
2. **Re-sending a join request to the same plan on the same day** (after a decline or withdrawal) must not use a second slot (Task 1 test).
3. **Premium ending while "Hosted by" is set** must quietly reset the filter to Everyone, not show an error screen (Task 6 test on `premiumBlock` and the reset rule).
4. **The webhook arriving for an anonymous or unknown RevenueCat id** (`$RCAnonymousID:…`, or a user who has deleted their account) must return 200 and change nothing, or RevenueCat will retry forever (Task 3 test).
5. **A purchase that succeeds in Google while the server sync fails** must still show Premium once sync succeeds (on retry, foreground or Restore), and must never block the user with a crash (Task 4 test).

**Interfaces:**

RLS: select only where `user_id = auth.uid()`. No insert, update or delete grants for `anon` or `authenticated`.

  - Do nothing unless `auth.uid() = p_user`.
  - Day = IST date.
  - If `(p_user,p_kind,day,p_ref)` already exists, return (a re-send).
  - If not `has_premium(p_user)` and today's count for that kind is at least the limit (plan 3, join 10), raise `daily_plan_limit` or `daily_join_limit`.
  - Otherwise insert the usage row.

### Task 3: RevenueCat webhook and app sync (edge function)

**Files:**
- Create: `supabase/functions/_shared/premiumHandler.ts`, `supabase/functions/revenuecat-webhook/index.ts`
- Modify: `supabase/functions/README.md` (add the two secrets and the deploy line `supabase functions deploy revenuecat-webhook --no-verify-jwt`)
- Test: `tests/premiumWebhook.test.ts`

**Interfaces:**
- Consumes: the `premium_entitlements` table (written with the service role).
- Produces: `createPremiumHandler(deps: { db: any; webhookSecret: string; revenueCatKey: string; fetch: typeof fetch }): (req: Request) => Promise<Response>`. It has two modes, chosen by the `Authorization` header:
  - **Webhook mode:** the header equals `Bearer ${webhookSecret}`.
    - Read `event` from the JSON body.
    - Collect the UUID-shaped ids from `app_user_id`, `original_app_user_id`, `aliases[]`, `transferred_from[]` and `transferred_to[]`; ignore anything else.
    - `refresh(id)` each one, then return `200 {"ok":true}`.
  - **App sync mode:** any other `Bearer <jwt>` with body `{"action":"sync"}`.
    - Look the user up with `db.auth.getUser(jwt)`. Return 401 if that fails.
    - `refresh(user.id)`, then return `200 {"expires_at": string | null}`.
    - Anything else gets 400; a missing header gets 401.
  - **`refresh(id)`:**
    - `GET https://api.revenuecat.com/v1/subscribers/${encodeURIComponent(id)}` with `Authorization: Bearer ${revenueCatKey}`. A non-2xx response throws, and the handler returns 502 so RevenueCat retries.
    - Read `subscriber.entitlements.premium`. If it is absent, delete the user's row.
    - Otherwise `expires_at` is the later of the entitlement's `expires_date` and `subscriber.subscriptions[product_identifier].grace_period_expires_date`. A null `expires_date` means `9999-12-31T00:00:00Z`.
    - Upsert `{ user_id, expires_at, product_id: product_identifier, store: subscription.store ?? null, updated_at }` on `user_id`.
    - A foreign-key error (code `23503`, deleted account) is ignored.
  - Never trust the webhook body for status: only RevenueCat's API decides.
- `index.ts` follows `review-verification/index.ts`. It returns 503 when `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `REVENUECAT_WEBHOOK_SECRET` or `REVENUECAT_API_KEY` is missing.

**Files:**

- Create: `src/services/purchases.ts` (the RevenueCat adapter; the only file importing `react-native-purchases`, loaded with a lazy `require` behind `Platform.OS === "android"` and the env key)
- Modify: `package.json` via `npx expo install react-native-purchases`
- Test: `tests/premium.test.ts`

**Interfaces:**
- Consumes: the `premium_entitlements` select (RLS own row) and the `revenuecat-webhook` sync from Task 3 via `supabase.functions.invoke("revenuecat-webhook", { body: { action: "sync" } })`.
- Produces (in `premium.ts`):
  - `type PremiumReason = "plans" | "joins" | "filter" | "profile"`
  - `type PremiumPlanId = "weekly" | "monthly" | "quarterly"`
  - `type PremiumPlan = { id: PremiumPlanId; priceString: string; price: number; savingsPercent: number | null; pkg: unknown }`
  - `type PremiumSnapshot = { status: "loading" | "free" | "premium" | "unavailable"; expiresAt: string | null; plans: PremiumPlan[]; busy: boolean }`
  - `interface PurchasesAdapter { identify(userId: string): Promise<void>; plans(): Promise<Omit<PremiumPlan, "savingsPercent">[]>; purchase(pkg: unknown): Promise<"done" | "cancelled">; restore(): Promise<void>; signOut(): Promise<void> }`
  - `premiumBlock(message: string): PremiumReason | null`: `daily_plan_limit` → `"plans"`, `daily_join_limit` → `"joins"`, `premium_required` → `"filter"`, anything else → `null`.
  - `planSavings(plans): PremiumPlan[]`: percent saved against the weekly price × weeks (monthly 52/12, quarterly 13), rounded down; null for weekly or when weekly is missing.
  - `class PremiumStore`:
    - Constructor takes `{ adapter: PurchasesAdapter | null; userId: string; demo: boolean; readExpiry(): Promise<string | null>; sync(): Promise<string | null>; now?: () => Date }`.
    - `subscribe`, `getSnapshot` (for `useSyncExternalStore`).
    - `load()`: identify, read expiry, load plans.
    - `purchase(id: PremiumPlanId): Promise<"done" | "cancelled">`, `restore(): Promise<void>`.
    - Status is `premium` when the expiry is in the future. Otherwise it is `unavailable` when the adapter is null or `demo`, and `free` the rest of the time.
    - After a `"done"` purchase or a restore, call `sync()`. If sync throws, keep the previous status, rethrow `new Error("Your purchase went through. We're still confirming it — tap Restore in a minute.")`, and leave the store usable.
  - `purchases.ts` exports `createRevenueCatAdapter(): PurchasesAdapter | null`:
    - Returns null without the key, off Android, or if the native module is missing.
    - Map package types `WEEKLY`, `MONTHLY` and `THREE_MONTH` to `weekly`, `monthly` and `quarterly`.
    - `userCancelled` errors mean `"cancelled"`.

  - `planSavings` with weekly 49, monthly 149 and quarterly 349 gives null, 30 and 45.
  - The store is `premium` when `readExpiry` returns a future date, even with a null adapter.
  - The store is `unavailable` with a null adapter and no expiry, and also in demo, where `purchase()` rejects without calling the adapter.
  - `purchase("monthly")` calls the adapter with the monthly `pkg`, then `sync`, and the status becomes `premium`.
  - A cancelled purchase does not call `sync`, and the status stays `free`.
  - When sync throws after a purchase, the store rejects with the "still confirming" message, `busy` returns to false, and a later `restore()` with a working sync becomes `premium` (Review Focus 5).
